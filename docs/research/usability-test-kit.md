# 利用者テストの手順（Tab Studio と競合の比較）

`feature-strategy-2026-10-18.md` の比較表と、新機能の成功指標を確かめるための台本です。実施するのはあなたです。

## 対象と準備

- **参加者**：ギタリストまたはベーシスト3〜5人。
  - TAB譜ソフトの経験者と未経験者を混ぜます。
  - 普段使っているソフトを記録します。
- **ソフト**：Tab Studio（Tauri版）、MuseScore Studio（できれば最新の4.7.x）、TuxGuitar（できれば2.1.0）。Guitar Pro 8の体験版も使えれば加えます。
- **順番**：ソフトの順番は参加者ごとに入れ替えます（慣れの影響を打ち消すため）。
- **素材**：課題ごとに同じ素材を全ソフトに用意します。曲は `Desktop\譜面` から2曲を選び、同じ内容をGP形式で配ります。
- **記録**：画面録画（OBSなど）を使います。時間は録画から測ります。

## 課題（各ソフトで実施）

| # | 課題 | 測る項目 |
|---|---|---|
| T1 | 白紙から4小節のリフを入力する（配った譜面の画像を見ながら。8分音符16個、6弦と5弦、ハンマリング1か所、ベンド1か所） | 完了時間、誤り数、ヘルプを見た回数 |
| T2 | 既存の曲の8小節を選び、60%の速度でループ再生し、3周ごとに5%ずつ上げて80%まで練習する設定をする | 設定を終えるまでの時間、できたかどうか |
| T3 | 伴奏の音声ファイル（同じ曲）を読み込み、譜面とずれないように合わせる | 合わせ終えるまでの時間、残ったずれの主観評価（1〜5） |
| T4 | 曲全体を半音下げ、TABのフレットが自然になっているかを確認する | 時間、不自然な運指を指摘した数 |
| T5 | MusicXMLファイル（MuseScoreで作ったもの）を開いて再生する | できたかどうか、表示の崩れ |
| T6（Tab Studioのみ） | 楽器をつないで2小節を弾き、直近の録音から保存する | 時間、迷った場所 |

**進め方**
- 課題の前に1分間、ソフトを自由に触ってもらいます。課題中は助言しません（詰まったら、5分で打ち切り）。
- 考えていることを口に出してもらいます（発話思考法）。迷った箇所は録画から書き出します。

## 質問票

### SUS（System Usability Scale）

ソフトごとに記入します。1＝全くそう思わない、5＝強くそう思う。

1. このソフトを頻繁に使いたい。
2. このソフトは必要以上に複雑だと感じた。
3. このソフトは使いやすいと感じた。
4. このソフトを使うには、詳しい人の助けが必要だと思う。
5. このソフトの機能はよくまとまっていると感じた。
6. このソフトには一貫性のないところが多いと感じた。
7. たいていの人は、このソフトをすぐに使えるようになると思う。
8. このソフトはとても扱いにくいと感じた。
9. このソフトを自信を持って使えた。
10. このソフトを使い始める前に、多くのことを学ぶ必要があった。

**採点**：奇数番は（点−1）、偶数番は（5−点）にして合計し、2.5倍します（0〜100点）。68点前後が平均とされます（Brooke 1996）。

### 練習についての追加の質問（自由記述）

- いつもの練習で一番時間を取られている作業は何か。
- 「どこを間違えたか」を今どうやって確かめているか。
- 欲しい機能を3つ挙げるとしたら何か（こちらからは例を示さない）。

## 新機能の試作を確かめる手順（N1の例）

1. 単音のフレーズ3本を、ゆっくり・普通・速いの3段階で録音します（DI）。
2. 正解データを作ります。各音の発音時刻を、音声編集ソフト（Audacityなど）の波形から手で付けます。2人で別々に付け、差が20msを超える音は話し合って決めます。
3. 試作の検出結果と比べ、±50ms以内を正解としてF値を計算します。**合格ラインは0.90**です（事前に固定し、結果を見てから変えません）。
4. 利用者課題として、「一番崩れている小節を指してください」と頼みます。ヒートマップあり／なしで時間を比べます。参加者内で順番を入れ替えます。

## 結果のまとめ方

- 課題ごとに、ソフト別の中央値と範囲を表にします（人数が少ないので平均は使いません）。
- 比較表（`feature-strategy-2026-10-18.md` §4.1）の「?」と「推測」を、確かめた結果で書き換えます。
- 予想と違った点は、そのまま記録します。都合のよい結果だけを残しません。
