# Tab Studio 汎用化のための調査と提案

作成日：2026-10-18 ／ 基準：Tab Studio 1.3.0（tauri-migration ブランチ c4e0b7d）／ 状態：調査のみ・未実装

## 0. 要約

- **一番の問題は保存・書き出しで起きている欠損。** 手元の実譜面65件で測った結果です。新機能より先に、これらを直す価値が高い。
  - **GP7への書き出しで、制御点が5個以上のベンドがすべて消える**（16件・903個。元はGP5が3件、TGが13件）。
    - 原因はalphaTab 1.8.4の書き出し処理です。`_writeBend` が `bendPoints.length <= 4` のベンドしか書きません。
  - **GP7をMuseScoreで開くと、6曲中2曲が「破損」と判定される**。2/4・3/4拍子の小節で、第2声部が「全音符の長さ」になっているためです。
  - **大きな曲をTGで保存すると失敗する**。360小節・11トラックの曲が40MBの上限を超えました。保存はエラーで止まり、代わりの保存方法はありません（コードで確認）。
  - **TGファイルは元の約6.8倍の大きさになる**（中央値）。
  - **TG形式での欠損の多くは、Tab Studio自身のTG読み込み処理が原因**。ストローク、トレモロピッキング、装飾音、トリル、コード、歌詞を「初期版では省略」しています。
    - つまり、TuxGuitarで作ったTGを開くと、これらが失われます。
    - 書き出し側も、歌詞・コード・装飾音を書いていません。
  - Tab Studioが保存するTGは「TuxGuitar_file_format 2.0.0」です。このPCのTuxGuitar 1.6.4では開けない見込みです（TuxGuitarのリリースノートより。未実測）。
- **MusicXMLの読み込みは、半分だけ実現できている。**
  - 描画エンジン alphaTab 1.8.4 は、変換した実譜面22件をすべて読めました。ファイル選択の「すべてのファイル」から選べば、コード上は読み込み処理まで届きます（アプリでは未確認）。
  - ただし、同じ曲のGP5/TGと音高と発音時刻で比べると、一致率（再現率）は0.73〜1.00でした。複数トラックの曲では、**TABの弦・フレットが付く音は0〜18%しかありません**。
    - 実用にするには、運指の自動割り当て（N5）が必要です。
  - MIDIの読み込みは対応していません（実測）。
- **MusicXMLの書き出しを後回しにできるとは言えない。** GP7経由でMuseScoreに渡す方法は、上の「破損」判定を直すまで当てになりません。
- **練習機能は、基本的なものがすでに競合と並んでいます。** カウントイン、スピードトレーナー、ループ、伴奏音声とYouTubeの同期はあります。
  - 不足は2つです。曲の途中で伴奏とのずれを直す「同期点」（Guitar Pro 8・Soundsliceにはある）と、演奏を聴いて評価する機能。
- **Tab Studioにしかない強み**：ASIOのライブ入力、直近5分の常時DI録音（譜面位置の印つき）、NAM・VST3、往復遅延の実測。
  - これらを譜面と結びつける機能（§6のN1・N3・N4）は、同じ形の**製品**は見つかりませんでした。
  - ただし、N1には近い**特許**があります（US 8,338,684／US 8,785,757、TAB上の誤り表示）。近い製品もあります（Rocksmith、Yousician、Songsterr AI）。新しいのは「組み合わせ」の部分だけです。

確信度の表記：**高**＝実測・コードで確認／**中**＝公式資料で確認／**低**＝間接的な資料・推測。出典のない競合の情報は「推測」と書きます。

### 自動往復テスト（`docs/research/interop-harness/`）

- `census.mts`：アプリと同じ処理（`importTg`／`importGuitarPro`／`exportScore`）で読み込みます。
  - 約60種類の記譜要素を数えたうえで、次の3通りで書き出して読み直し、差を数えます。
    - GP7
    - TG（アプリの補足データあり）
    - TG（補足データを除いたもの＝**TuxGuitarが読む部分**）
  - 音符は（トラック, 小節, 声部, 拍の位置, 音価, 付点, 弦, フレット, タイ）の組で照合し、一致率（noteMatch）を出します。
- `agg.mjs`：集計します。`bend.mts`：ベンドの欠損を追跡します。`size.mts`：保存サイズを分析します。`exp.mts`：MuseScoreでの読み込み試験用に書き出します。
- 実行方法（Tab Studioのフォルダーで）：`node --import tsx docs/research/interop-harness/census.mts out.json <ファイル…>`
- スクリプト内の絶対パスは、このPCの構成に合わせています。

### 3.2 カスタムベンドの消失（再現手順）

`bend.mts` を `Aerosmith-Dream On-01-17-2026.tg` に使った結果：

```
before {bar:49, type:1, pts:'0:0 0:0 30:0 30:0 60:2'}  → after: bendType 0, 制御点なし
before {bar:57, type:1, pts:'0:0 0:0 30:4 30:4 60:8'}  → after: bendType 0, 制御点なし
```

**原因（確定）**
- `node_modules/@coderline/alphatab/dist/alphaTab.core.mjs` の `Gp7Exporter._writeBend` は、`if (note.hasBend && note.bendPoints.length <= 4)` の場合しか書きません。
- 実際に、Dream On（GP5とTG）を書き出したscore.gpifには、`Bended` プロパティが0個でした（元のベンドは18個）。
- Hotel Californiaでは、4点以下の12個だけが書き出されました。
- GP3〜5のベンドは点の数が多く、Tab StudioのTG読み込み処理もベンドを5〜6点で作るため、どちらから来たベンドも落ちます。

**対策**：`src/export-score.ts` で、書き出す前のコピーに対して、ベンドを4点以下に近似します（元の譜面は変えない）。alphaTabへの報告もあわせて行います。

### 3.3 TGファイルの大きさ

- TGの補足データは、alphaTabのJSONを丸ごと持っています。さらに`contentXml`として、TG本体のXMLの複製も持っています（`src/tg-writer.ts:79`）。
- その結果、TGは元のファイルの**約6.8倍（中央値）、最大13.5倍**になりました。
- 360小節・11トラックの曲（元のGPは130KB）では、JSONだけで34.3MBになります。そのうち`beat.notes`が12.6MBでした。
- アプリの保存（`src/main.ts` の `writeDocument`）は、同じ `encodeDocument('save')`→`exportTg` を通ります。そのため、この曲は保存できません。例外で処理が止まり、代わりの保存先はありません。アプリ上での再現はしていません（確信度：中〜高）。

### 3.4 MusicXML・MIDI

| 試験 | 結果 |

| 同じ曲のGP5/TGとMusicXMLを、（小節, 発音時刻, 実音高）で照合（`mxcmp.mts`、7組） | 再現率は Hotel California 0.87、Dream On 0.73、Stairway 0.94、Achilles 0.99、Time_measures 0.99、BW&BW2 1.00。**弦とフレットが付いた音の割合**は 0.18／0.12／0.00／1.00／1.00／0.58。TAB譜表の数はHotel California 1/7、Stairway 0/11。MSCZ自体がGPからMuseScoreに取り込んだものなので、差の一部はMuseScore側の取り込みによる |

## 6. 新機能の案

### 共通の前提
- Tab Studioにはすでに次の土台があります。
  - 常時DI録音と、20msごとの譜面位置の印
  - 往復遅延の実測値
  - NAMでの再アンプ
  - 伴奏音声の整列
- この土台を「譜面に戻す」ことが、他の製品にない価値になります。
- 各案の「先行例」は、§7の検索語で調べた結果です。

### N1 演奏照合ヒートマップ
- **解決する作業**：自分の演奏のどこが走る・遅れる・抜けるかを、譜面の上で確かめたい。
- **内容**：テイクのDIを解析し、各音の発音時刻と音高を、その時の譜面位置の印と照合します。結果をTAB上で色分けし、音ごとのずれ（ms）、音高の違い、弾き逃しを表示します。遅延は実測値で補正します。
- **先行例**：
  - Yousician：正確さとタイミングを採点。ただし内部の仕組みは非公開で、音ごとのずれは出さない。
  - Rocksmith+：音の検出と正確さに応じた難易度調整。ただし自分が書いた譜面には使えない。
  - 編集できる任意の譜面に、自分の機材の音とミリ秒単位で重ねる製品は見つかりませんでした（確信度：中）。
  - **特許**：US 8,338,684／US 8,785,757「Musical instruction and assessment systems」は、TABを含む譜面上に「音の誤り」と「タイミングの誤り」の領域を重ねて表示し、正答率を出す構成を記載しています。
    - 考え方そのものは新しくありません。
    - 権利がまだ有効か、請求項の範囲はどうかは確認していません。**製品化する前に専門家の確認が必要です。**
- **実装方針**：
  - `src-tauri/src/live_input.rs` の録音と印を使い、Rust側に解析用のモジュールを足す。
  - 発音の検出はスペクトルフラックス、音高はYIN/pYIN。
  - 表示は`src/hit-test.ts`の座標を使って重ねる。
- **最小の試作**：単音フレーズ限定。録音後に解析し、小節ごとの平均ずれだけを表示する。
- **成功指標（事前に決める）**：
  - 手で正解を付けた3テイクで、発音検出のF値0.90以上（許容±50ms）。
  - 利用者テストで「最も崩れている小節を見つけるまでの時間」がヒートマップなしより30%短い。

### N2 正確さで上げ下げするスピードトレーナー
- **内容**：N1の結果を使い、「±30ms以内の音が90%以上」なら次の速度へ、未満なら据え置くか下げます。
- **先行例**：Rocksmith 2014のRiff Repeater「Accelerator」は、腕前を検出して速度を自動調整していました。**新しさは低い**です。差別化できるのは、条件が見えることと、利用者が条件を決められることだけです。
- **実装**：`src/practice.ts`の`SpeedTrainer.complete()`に合否の判定を渡すだけです。
- **成功指標**：同じフレーズで、目標テンポに到達するまでの周回数が、固定の上げ幅より少ない（被験者内比較、5人×2フレーズ）。

### N3 弱点小節の分散練習スケジューラ
- **内容**：
  - N1の小節ごとの誤り率を、日をまたいで記録します。
  - 次回の練習の最初に「前回崩れた小節」を、間隔を空けて出題します（Leitner方式）。
  - 曲構成ナビに練習の予定を表示します。
- **学習科学の根拠**：分散練習の効果（Simmons 2011）、交互練習（Shea & Morgan 1979）。
- **先行例**：Modacityは「分散学習」をうたっていますが、仕組みは非公開で、譜面の小節や実測の正確さとは結びついていません（確信度：低）。
- **最小の試作**：記録と一覧表示のみで、出題順は手動。
- **成功指標**：1週間後の保持テスト（スケジュールあり／なしで誤り率を比較）。

### N4 「さっきの演奏を譜面に」（さかのぼり採譜）
- **内容**：常時録音の直近の演奏から1フレーズを選び、譜面の現在位置にTABとして書き込みます。
  - 譜面の再生中に弾いたものなら、印からテンポと小節線が分かるので、量子化の誤りを減らせます。
  - 弦とフレットはN5で決めます。
- **先行例**：
  - Songsterr AI：YouTubeや録音からTABを生成（Heiseの検証では、パームミュートとスライドをよく取りこぼす）。
  - Guitar2Tabs（Muse Group）。
  - Ableton Live の Capture（MIDIのみ）。
  - 「編集中の譜面に、常時DI録音からさかのぼって書き込む」形は見つかりませんでした（確信度：中）。
- **最小の試作**：単音・クリーンなDI・譜面の再生中に弾いたフレーズに限定する。
- **成功指標**：GuitarSet（ISMIR 2018）の単音部分と自分のテイク10本で、音高と音価の一致率80%以上。修正にかかる時間が手入力の半分以下。

### N5 運指の最適化と「弾きやすさ」表示
- **内容**：
  - 選んだ範囲の（弦, フレット）を、手の移動・指を開く幅・開放弦を考えた費用で、ビタビ法により決め直します。「5ポジションで」のように条件も付けられます。
  - 小節ごとの難しさ（移動量・幅）を色で示します。
  - G10（MIDI読み込み）とG3（MusicXML読み込み）の後処理にも使えます。
- **先行例**：
  - MuseScoreのプラグインFretPath（ビタビ法）。
  - 研究：Sayegh 1989、arXiv 2407.09052。
  - 主要なTABエディタに標準で入っているものは見つかりませんでした（確信度：低）。**新しさは中**。
- **実装**：Rust coreに純粋関数として入れる。変更は既存の編集処理（`src/app/edit-transaction.ts`）で1回の取り消し単位にする。
- **成功指標**：ギタリスト3人が、手書きの運指と比べて「同等以上」と評価する割合が70%以上。

### N6 伴奏音声の自動同期点
- **内容**：譜面のMIDIと音声のクロマ特徴をDTWで整列し、小節ごとの同期点を自動で置きます（G4の上に作る）。
- **先行例**：
  - Soundsliceの「Sync with notation」（有料プラン、小節内の同期点にも対応）。
  - GP8は手動のみ。
  - **新しさは低い**ですが、オフラインかつ無償という点で差別化できます。
- **成功指標**：手で付けた同期点との差の中央値が50ms以下（5曲）。

### N7 区間ごとの音色シーン
- **内容**：曲構成の区間ごとに、NAMとFXの設定（例：Aメロはクリーン、ソロはリード）を譜面に保存します。再生中もライブ入力のモニターでも、自動で切り替えます。
- **先行例**：GP8のペダルボードは再生音向けです（ライブ入力の切り替えについては未確認）。Rocksmithは曲中に音色を切り替えます（推測）。**新しさは低〜中**。
- **実装**：`studio`の補足データに区間IDと設定IDの対応表を置き、`src/mixer-state.ts`へ渡す。

### N8 版の差分表示
- **内容**：同じ曲の2つの版（自動保存の時点やファイル）を比べ、変わった小節と音符を譜面上で色分けします。`src/snapshot-diff.ts`が出発点になります。
- **先行例**：MuseScore 3の比較ツール（文字の一覧）とプラグイン（概念実証）。2018年のGSoCの記録では、見た目で比べる方式は未実装。**新しさは中**。
- **成功指標**：意図的に10か所変えた2つの版で、10か所すべてを検出し、誤検出がないこと。

**優先する順番**：G1〜G3 → G4 → N1（試作）→ N2 → N5 → N4 → N3。N6〜N8は余力があれば。

N1は、N2・N3・N4の土台です。試作で精度を確かめるまで、N2以降には進まないことを勧めます。

## 9. 懐疑的レビュー（根拠の弱い点）

1. **一致率＝1.000は「同じ」の意味ではありません。** 照合する項目に含めていない属性（運指番号、奏法の細かい値、レイアウト）の差は検出しません。§3.1の「差なし」は、数えた約60項目についてだけです。
2. **［修正済み］TGの欠損は、最初「TuxGuitarが読む部分」と書いていました。** 実際に測ったのは、Tab Studio自身の読み込み処理での欠損です。読み込み・書き出しのコードで原因を分け、§3.1に書き直しました。TuxGuitar本体でどう表示されるかは、まだ測っていません。
3. **［修正済み］MuseScoreとの試験は、最初、強制オプション付きでした。** そのため「6/6で開ける」としていましたが、オプションなしでやり直すと、2/6が破損と判定されました。§0と§3.4を書き直し、G1bを追加しました。
4. **G2の保存失敗は、アプリの画面上では再現していません。** ただし、保存処理が同じ`exportTg`を通り、代わりの保存先がないことはコードで確認しました。
4b. **［修正済み］MusicXMLの読み込みは、最初「ほぼ実現」としていました。** 同じ曲どうしで比べると、再現率が0.73まで下がる曲があり、TABもほぼ付きませんでした。§0とG3を書き直しました。
5. **Reachの多くは推定で、実譜面はこのPCの利用者1人分です。** 利用者全体の分布ではありません。RICEの順位は、段階1の3件（実測の根拠がある）以外は入れ替わる余地があります。
6. **競合の欄の「?」と「推測」が多いです。** 特にGuitar Pro 8は本体で確かめていません。利用者テスト（`usability-test-kit.md`）で直接比べるまでは、比較表は暫定です。
7. **学習科学の文献はCrossrefで照合しました。**
   - Shea & Morgan 1979：doi:10.1037/0278-7393.5.2.179
   - Salmoni, Schmidt & Walter 1984：doi:10.1037/0033-2909.95.3.355
   - Simmons：doi:10.1177/0022429411424798（JRME、**2011**。本文の「2012」は誤りで、2011が正しい）
   - Ericsson ほか 1993とDuke ほか 2009は、照合の要求が制限（HTTP 429）に当たり、未照合です。
8. **KLMによる操作数の比較はしていません。** 競合の操作手順を本体で確かめられなかったためで、利用者テストの計測に置き換えています。
