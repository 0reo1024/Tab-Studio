# 楽器入力（常時録音・プラグイン練習）

Tauri 版のみ。フェーズ1の調査と計測は [live-input-phase1.md](live-input-phase1.md) にまとめた。

## 使い方

1. **ツール → 楽器入力（録音・練習）…** でパネルを開く。
2. **方式**を選ぶ。
   - **ASIO**(推奨):Nano Cortex などのドライバを使う。バッファは 64〜128 が目安。
   - **WASAPI(共有)**:他のアプリと同時に使えるが、遅延が約 40 ms ある。
3. **入力チャンネル**で楽器をつないだ入力を選び、**入力をオン**を押す。
   - 次にアプリを起動したときも、オンのまま始まる。
4. **アンプ(NAM)**と **VST3 プラグイン**を選ぶと、通した音でモニタできる。
   - プラグインの「編集」で、そのプラグイン自身の画面が開く。閉じると設定が保存される。
5. **常時録音**は「設定 → 一般 → 楽器入力」でオンにする(既定はオフ)。
   - オンのときは、直近5分がタイムラインに出る。
   - 操作は、ドラッグで範囲選択、クリックでそこから再生、ダブルクリックで1フレーズを選択。
   - 再生する音は3種類から選べる:聴いた音 / DI(素の音)/ DI を今のアンプで鳴らし直す。
   - 「譜面も一緒に」をオンにすると、録音したとき譜面を再生していた位置から譜面も鳴る。
   - 「選択範囲を保存」で、選んだ範囲をそのまま保存する。
   - 「保存を開始」は、指定した秒数だけ過去にさかのぼって保存を始め、「保存を終了」を押すまで書き続ける。
6. **遅延を実測…**:出力から入力へケーブルをつなぐと、クリック音1回で実際の往復遅延を測れる。

### 保存先

| 内容 | 場所 |
|---|---|
| テイク | `ミュージック\Tab Studio 録音\<日時> <アンプ名> DI.wav` と `… モニタ.wav` |
| テイクの付帯情報 | 上と同じ名前の `.json`(機器、アンプ、プラグイン、譜面の位置) |
| 常時録音の生データ | `%APPDATA%\jp.tabstudio.desktop\live\segments`(5分ごとのファイル。合計 2 GB を超えた分は古い順に削除。アプリが落ちても直前まで残る) |

- WAV はどれも 48 kHz・32bit float・モノラル。
- 「モニタ」の WAV は聴いていた音(アンプやプラグインを通した後)。DI より数 ms 遅れている。

## 仕組み

```
入力コールバック ─ InputTap ─┬─ モニタ用リング ─→ LiveStage(エンジンの出力コールバック内)
                             │                       入力ゲイン → NAM → 挿入エフェクト(外部VST3はライブ用リンク)
                             │                       → 出力へ。聴いた音は録音用リングへ
                             └─ 録音用リング(DI) ─→ Recorder スレッド:直近5分(メモリ)
                                                     + 5分ごとのWAV(ディスク)+ テイク
```

- **デバイス**(`crates/tabstudio-audio/src/device.rs`)
  - 出力は WASAPI か ASIO。ASIO では入力ストリームを先に作る。こうすると cpal が毎回入力を先に処理するので、モニタは同じバッファの入力を鳴らせる。
  - デバイスの切り替えや入力のオン/オフでは、エンジン本体とタップを閉じたストリームから受け取り直す。曲やミキサーは読み込んだまま残る。
- **自動復旧**(`src-tauri/src/live_input.rs` のデバイススレッド)
  - デバイスが消えたことを示すエラー(抜けた、ドライバのリセットなど)を検知すると、同じデバイスを開き直す。
  - 開けない間は既定の出力で鳴らし続け、デバイスが戻ったら元に戻す。
- **遅延の詰め方**(`live.rs`)
  - 入力が出力より余計に溜まった分は、0.5 秒ごとに捨てる(余白は 32 フレーム)。
  - 出力と入力が別のクロックの機器でも、遅延が増えていかない。
- **外部 VST3**
  - ライブ用リンクの遅延は、128 フレーム以上ならエンジンブロック2つ分(128 なら 5.3 ms)、それ未満なら3つ分(64 なら 4.0 ms)。
  - プラグインが報告する遅延は補正しない(ライブでは入力より先に音を出せない)。その分は遅延表示に足して見せる。
  - ホスト側のリンクスレッドは MMCSS「Pro Audio」で動かす。
- **録音の時刻合わせ**
  - DI の何フレーム目かがタイムラインの位置になる。
  - 「聴いた音」は DI と 1 対 1 で記録する(捨てた入力の分は無音で埋める)。
  - 譜面の再生位置は 20 ms ごとの印(マーク)として残す。

## ビルド(ASIO)

- 既定で `asio` feature が有効。必要なものは2つ。
  - Steinberg ASIO SDK を `third_party/asio_sdk` に置く(git には入れない。Steinberg のライセンスに同意して利用)。
  - LLVM(`C:\Program Files\LLVM`)。
- パスは `.cargo/config.toml` で指定している。
- SDK を用意できない環境では、`cargo build --no-default-features` で ASIO なしのビルドになる(パネルの「ASIO」が選べなくなる)。

## できていないこと・一部だけのこと(2026-10-15 時点)

- **無音で区切ったテイクの自動保存**:タイムライン上でフレーズの帯を表示し、ダブルクリックで選ぶところまで。フレーズごとのファイルを自動で書き出す機能はない。
- **プリセット**:モニタのチェーン(アンプ、トーン、プラグインとその状態)は1組だけ自動で保存される。名前を付けて複数を切り替える機能はない。
- **入出力が別の機器のときの再サンプリング**:していない。ずれは、溜まった分を捨てるか無音を足して吸収する(ASIO や同じ機器なら問題にならない)。
- **プラグインを通したときの遅延**:ASIO 128 + VST3 で約 20 ms。目標の 10 ms には届かない。64 にすると数 ms 縮む見込みだが、未計測。
