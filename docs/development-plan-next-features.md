# Tab Studio 追加機能の開発設計

作成日：2026-10-07 ／ 基準：0.3.36 ／ 状態：設計のみ・未実装

対象は提案項目 1 カウントイン、2 スピードトレーナー、3 奏法の詳細編集、4 曲構成ナビゲーター、5 目的別貼り付け、6 五線譜・ドラムの入力強化、10 譜面・印刷レイアウト。

## 1. 完成時の基本方針

- 普段の画面は現在の譜面・編集パレット・トラック・再生コントロールを基本形とする。
- 詳細機能は既存メニュー、既存ボタンの詳細画面、閉じられる補助パネルへ配置する。画面上部に機能ごとのボタン列を増設しない。
- 補助パネルは固定幅の同じ領域を共有し、曲構成・鍵盤・ドラム入力のうち一つだけ開く。譜面幅を確保できない窓では重ねて表示する。最後に使った表示状態を記憶するが、初回は閉じておく。
- 音符入力や方向キー移動は、譜面の描画完了・MIDI更新・自動保存を待たせない。
- 編集中の選択、再生位置、表示位置はそれぞれ独立した状態として管理する。
- 初回の追加機能は既定で無効または閉じた状態。既存設定は移行し、ショートカットを勝手に上書きしない。

### 変更しない操作上の約束

1. Spaceは通常の再生・その場で停止。ループ／トレーナー中はそれらも解除する。
2. Ctrl+Spaceは再生開始位置へ戻って停止。カウント中も開始待ちを取り消す。
3. 範囲選択中の通常再生は、選択直前の緑枠の位置から始める。選択の青枠は維持し、再生中は緑枠も表示する。一時停止後は停止位置から再開する。
4. 明示的なループ／トレーナーの開始だけは、その指定範囲の先頭から始める。
5. 通常の貼り付けは確認画面なし。Ctrl+Shift+Vは現在の「挿入して貼り付け」を維持する。
6. TABの数字入力中は音を鳴らさず、Enterまたは移動による確定時に試聴する。入力は数字のみ。
7. 音符・休符の選択だけでは譜面データを変更しない。
8. エラー・お知らせは左下の12px表示を使い、譜面の配置を動かさない。
9. 機能追加によって「編集モード」の切り替えを復活させない。

## 2. 現状の調査と改善対象

| 現在の構成 | 評価と今後の扱い |
|---|---|
| src/main.ts に編集・再生・選択・メニュー等が集中 | 一括書き直しは行わず、追加機能の接続点から責務を分離する。既存テストを通しながら段階的に移す。 |
| 通常フレット入力は local-fret-edit / edit-snapshot / fret-feedback を使用 | 変更した拍の更新、履歴の部分コピー、即時の表示、描画のまとめ処理を基準にする。 |
| 汎用 commit は normalizeEdit による全曲の変換・再構築を行う場合がある | 奏法・強弱・コード等にも局所更新を拡張する。単に処理をWorkerへ移すだけでは、転送用の全曲コピーが残るため不十分。 |
| 貼り付けは範囲の抽出が改善済みだが、結果の全曲再構築が残る | 対象声部・小節と必要な前後関係を計算し、まとめて確定する経路を追加する。 |
| 描画は Worker、変更開始小節、背景描画を利用 | 行の再配置が後続へ波及する点は残る。完全な「1小節だけの再描画」が常に可能とは仮定しない。 |
| MIDIは編集後の再生開始時に更新する経路がある | 音の高さ・音価・奏法などが変わった場合だけ更新する。選択、画面移動、印刷設定は更新対象にしない。 |
| ClickAudio は短いクリック音をキャッシュし、通知時点で再生 | 任意時刻の予約・取り消しを扱える構成が必要。カウントと本演奏の接続を先に実測する。 |
| alphaTab の同梱型定義には countInVolume、lineBreaks 等がある | APIが存在することと必要な動作ができることは別。小節数、拍子、音色、周回境界、手動改行を試作で確認する。 |
| TGは content.xml 内の TabStudioProject に補足情報を保存 | 新しい譜面・レイアウト情報の保存に利用する。TGのZIPに独自の3つ目のファイルは追加しない。 |
| PDFは別画面で描画し、範囲・倍率・向き・個別トラック出力に対応 | 既存機能を拡張する。印刷処理を通常編集の描画処理に混ぜない。 |

## 3. 共通のプログラム構成

以下は追加・分離する責務の案であり、現時点でファイルの実装は行わない。

| モジュール案 | 責務 |
|---|---|
| editor-session | 文書、選択、入力中の値、再生位置、表示位置、現在の補助パネルを管理 |
| edit-commands / edit-transaction | 編集要求の検証、適用、取り消し、変更範囲の通知 |
| render-scheduler | 描画要求の集約、世代管理、画面外の処理の優先度調整 |
| playback-controller | 停止・準備・カウント・通常再生・ループ・トレーナーの状態管理 |
| practice-controller | 練習範囲、速度段階、完了周回数、終了条件 |
| audio-scheduler | 同じ音声時計に基づくクリック予約、キャンセル、開始同期 |
| technique-editor | 奏法の設定、適用条件、プレビュー |
| section-navigation | 曲構成の索引、ジャンプ、区間選択 |
| paste-service | 貼り付け種類ごとの変換、拍位置の対応、反復貼り付け |
| note-input / midi-input | 五線譜、画面鍵盤、ドラムパッド、MIDI入力の共通処理 |
| layout-settings / print-layout | 画面用の読みやすさ、印刷用のページと改行設定 |

### 編集の共通経路

操作 → 入力状態の即時更新 → 対象範囲の検証 → 編集を一括確定 → 必要な表示だけ更新 → 描画・再生データ・保存を必要に応じて予約する。

- 1操作を1つの取り消し単位にする。ベンドの点のドラッグ、和音入力、連続貼り付けも同様。
- コマンドは対象文書と対象音符を受付時に保持する。非同期処理完了時の「現在の選択」に適用してはいけない。
- 参照にはアプリ側の安定した識別子と文書世代を使う。描画用モデルのIDや小節配列の添字だけに依存しない。
- 貼り付け・削除・取り消しで識別子を維持／更新する規則を決める。対象が消えた古い要求は別の音符へ適用しない。
- 変更通知には、対象トラック・小節・声部と、音高／音価／奏法／構造／レイアウトの区分を含める。
- 単純変更は差分を履歴に保存する。構造変更は必要な範囲のスナップショットを併用する。既存の全曲復元経路は移行中の安全な代替として残し、使用頻度を測定する。
- 不正な編集は確定前に拒否し、失敗時に一部だけ譜面が変わった状態を残さない。

## 4. 1：カウントイン

### 画面と操作

「プレーヤー → 練習設定…」に「カウント：なし／1小節／2小節」「ループの各周回で鳴らす」を配置する。既定はなし。カウント中は既存の時間表示の領域に残り拍数を表示し、再生欄の高さを変えない。

- 通常再生の開始、明示的なループ／トレーナー開始で適用する。
- 一時停止からの再開は既定で即時再開。再開時もカウントする設定を詳細欄に置く。
- カウント中のSpaceは開始待ちを取り消し、停止状態へ戻る。数秒後に勝手に再生が始まる状態を防ぐ。
- カウント中のCtrl+Spaceは開始待ちを取り消し、開始位置へ戻る。
- カウント中に文書を切り替えた場合も、予約されたクリックと再生要求を取り消す。

### 時刻と拍子

開始位置の拍子と実効テンポを使う。既存メトロノームと拍の分割を合わせ、4/4、3/4、6/8、変拍子、途中のテンポ変更を検証する。クリック無効時でも、カウントを有効にした場合はカウント音だけを鳴らせるようにする。

音声の時刻を基準に短い音を事前予約し、画面タイマーは表示だけに使う。音声エンジンの標準カウントが要件を満たす場合は利用する。満たさない場合は同じAudioContextで予約するが、本演奏を指定時刻に開始できるかを先に検証する。メイン画面のタイマーだけで同期精度を保証しない。

## 5. 2：スピードトレーナー

「プレーヤー → スピードトレーナー…」に次をまとめる。

- 対象：既存のループ範囲、または選択範囲を取り込む。
- 開始速度・終了速度・上げ幅・各速度の周回数。
- 例：60% → 100%、5%刻み、各3周。
- 終了速度で指定回数を終えたら停止を既定とする。「終了速度で続ける」も選べる。
- 実行中の速度・周回は既存の練習速度／時間表示の領域を使う。音楽データのBPMは変更しない。

速度は周回境界でだけ変更する。曲中のテンポ変更には倍率として適用する。小節内の選択は音楽上の開始・終了位置として保持し、MIDI更新後に再生位置へ解決し直す。

内部のリピート、カッコ、任意のシークを「練習範囲を1周した」と誤認しない。単に再生tickが小さくなった回数を数える方式は採用しない。周回完了を音声側から判別できるかを試作段階で確認する。

Spaceで停止したらループとトレーナーの実行状態も解除する。次のSpaceは通常再生。ユーザーが指定した練習設定は記憶する。Ctrl+Spaceで停止した場合も自動再開や自動加速は起こさない。練習中の倍率とユーザーの通常倍率は別に持ち、終了時に通常倍率を復元する。

## 6. 3：奏法の詳細編集

### 表示を増やさない配置

編集パレットと編集ポップアップの並びは基本的に維持する。既存の奏法ボタンは素早いオン／オフを担当し、右クリックまたはメニューの「詳細…」から詳細設定を開く。設定済みの奏法は値の要約をツールチップに表示する。

### 実装対象

| 奏法 | 詳細設定 |
|---|---|
| ベンド | 半音単位等の上げ幅、プリベンド、リリース、ベンド＋リリース、点を動かすカーブ編集 |
| スライド | 入り／抜け、方向、レガート等の種類、接続先の条件 |
| ハーモニクス | ナチュラル、人工、ピンチ、タップ等、対応する発音・位置情報 |
| ビブラート・トリル・トレモロ | 対応モデルの範囲で強さ、相手の音高、刻みの速さを指定 |

まずベンド、その後にスライド・ハーモニクス、残りの詳細指定という順に完成させる。表示だけできて再生・保存に反映されない機能は完成としない。

### 編集処理

カーブをドラッグしている間は小さなグラフだけを更新する。譜面全体の再描画、MIDI再生成、履歴追加、試聴は行わない。適用で1回だけ確定し、プレビュー音は明示的な試聴操作か確定時に鳴らす。

複数選択の混在値は「混在」と表示し、ユーザーが変更した項目だけを適用する。タイ・ハンマリング・スライドは前後の関連音まで検証する。適用できない組み合わせは理由と位置を示し、途中まで変更しない。

TGの通常領域、独自補足領域、GP書き出しについて、奏法ごとの保存・復元表を作る。他ソフト経由では維持できない項目を識別し、変換情報として報告する。

## 7. 4：曲構成ナビゲーター

「表示 → 曲構成」で開く補助パネルに、既存の小節マーカーを一覧表示する。新しいマーカー情報を二重管理しない。

表示項目は名前・小節範囲・現在の区間。クリックでその区間の先頭へ移動し、右クリックで「区間を選択」「ループ範囲に設定」「名前変更」を行えるようにする。区間の選択だけでは再生位置を変えない。ジャンプ操作と範囲選択操作を混同しない。

区間の終わりは次のマーカー直前、最後の区間は曲末とする。小節の挿入・削除・複製に追随し、同名の区間も区別できる識別子を持つ。前後の区間への移動はショートカット設定に追加し、既存の割り当てと競合させない。

一覧の再計算はマーカーや小節構造が変わったときだけ行う。通常の音符入力や再生tickごとに全曲を走査しない。再生中は現在区間の強調だけを更新する。

## 8. 5：目的別の貼り付け

「編集 → 形式を選んで貼り付け…」を追加する。通常のCtrl+Vと挿入貼り付けは現在の即時動作を維持する。設定画面はこの追加コマンドを選んだときだけ開き、適用後の確認画面は出さない。

### 貼り付け種類

- リズムのみ：コピー元の音符・休符の開始時刻と長さを使う。音符位置では貼り付け先の同時刻に存在する音高群を使い、元が休符なら休符とする。コピー元の音高は持ち込まない。同じ音を細かく刻む結果になる箇所をプレビューで確認できるようにする。
- 奏法・強弱のみ：相対的な拍位置で対応付ける。音符単位の奏法は弦／音高の対応規則を明示し、適用先の音符がない箇所を知らせる。音高とリズムは変更しない。
- コード・テキストのみ：拍上の付加情報だけを貼り付ける。同じ種類の既存情報は置き換えることを画面に明記する。
- 指定回数繰り返す：コピーしたフレーズをN回まとめて貼り付ける。必要な末尾小節はまとめて追加する。
- 選択項目を組み合わせる場合、内容と配置方法「上書き／挿入」を別の設定として扱う。

打楽器と音程楽器の間でもリズムのみは許可する。音高を含む貼り付けでは既存の音域・弦数・チューニング検証を通す。

位置は配列の何番目かではなく音楽上の時刻で対応付ける。連符は整数比など誤差の蓄積しない単位で扱う。境界をまたぐ音、装飾音、全小節休符、異なる拍子、声部、タイの前後関係を仕様化する。無関係の全小節休符を操作だけで分割しない。

クリップボードは既存version 2を読めるまま、選択項目を記述できる次バージョンへ拡張する。N回貼り付けをN回のcommitとして実行せず、事前計算・検証後に1回の履歴として確定する。重い計算は対象範囲のデータだけをWorkerへ渡す。

## 9. 6：五線譜・ドラム入力の強化

### 共通方針

同じ補助パネル領域を、選択トラックに合わせて「鍵盤」または「ドラムパッド」に切り替える。毎回ダイアログを開かず入力できる。通常のTAB数字入力は現在の方式を維持する。

### 五線譜・画面鍵盤

- 音価は既存の編集パレットから選ぶ。鍵盤／五線譜上の操作で音高を指定する。
- 明示的な「和音に追加」操作と、通常の音符置き換えを分ける。
- 音高・臨時記号・オクターブは小さな補助欄で編集し、選択を維持する。
- 異名同音、調号、声部を考慮し、勝手な音高変換を避ける。
- ピアノ大譜表は選択中の段・声部に入力する。初期実装で左右の手へ自動振り分けは行わない。

### ドラムパッド

キック、スネア、ハイハット等を名称付きパッドで選ぶ。音価と選択位置は譜面側を使い、同時打ちは同じ拍に追加する。ノートヘッド・譜表位置・GMの音を共通の対応表で管理する。パッドへのショートカットは設定可能にするが、既存の奏法キーを自動で奪わない。

### MIDI鍵盤

初期実装は1拍ずつ確定するステップ入力とする。接続デバイス・入力チャンネル・入力先段／声部を選択する。複数キーを押した和音は、入力キーがすべて離された時点で1操作として確定し、次へ進む。

入力先文書と選択位置をNote On時に固定する。接続解除、パネル終了、文書切り替えでは鳴りっぱなしを止め、確定前の入力を整理する。再生開始時にはMIDI譜面入力を止め、再生中に意図せず譜面を書き換えない。

MIDIのライブ試聴は専用設定にし、ライブで鳴らした音を確定時に二重発音させない。TABの文字入力時の試聴ルールとは入力経路を分ける。リアルタイム録音と自動量子化は、この7項目の初期完成条件には含めない。

## 10. 10：譜面・印刷レイアウト

「表示 → 譜面レイアウト…」と既存のPDF出力設定から同じ設定へアクセスする。

### 画面用

現在の密度に応じた自動改行を基本に、譜面倍率、段間隔、トラック間隔、文字サイズ、任意の改行位置を設定する。1行4小節を強制しない。手動改行は自動計算への制約として扱う。

### 印刷用

用紙サイズ・向き・余白、改行・改ページ、タイトル・ページ番号、トラック名、奏法文字やコード図の間隔を追加する。既存の範囲指定・トラック別PDF出力を引き継ぐ。画面用と印刷用の設定は分離し、「画面の設定を印刷へコピー」で明示的に流用できるようにする。

音符・奏法文字・コード図・段同士の衝突を減らす。まず描画エンジンの設定で解決する。手動改ページは描画済みの段をページへ配置する層で扱う。必要な位置情報が取れるか、文字設定が楽譜全体に正しく効くかを試作で検証する。

任意のSVG要素を後からずらすだけの処理は、クリック判定と表示位置がずれるため採用しない。独自の配置補正が必要な場合は、描画・ヒットテスト・選択枠・PDFへ同じ結果を渡す。

設定中のプレビューは短い間隔で集約し、まず表示中の段を優先する。全ページの印刷プレビューとPDF出力は別の描画画面で実行し、編集用の選択やスクロールを変更しない。再生中は譜面配置を固定し、レイアウト設定の適用は停止後とする。

## 11. 遅延とストレスを減らす共通設計

### 処理の分離

1. 即時処理：入力中の数字、カーソル、選択枠、ボタン状態。目標は次の画面更新で反映。
2. 編集確定：対象音符／拍の検証とモデルの更新。通常編集で全曲を変換しない。
3. 背景描画：既存の約120msの集約を基準に実測調整する。モデル確定や次の入力を待たせるための遅延には使わない。
4. 再生データ：音に影響する変更だけを対象にする。通常は再生要求時に更新。準備中の停止要求は予約再生も取り消す。
5. 保存・印刷：確定した世代のデータを使用し、入力処理から分離する。

### 描画待ちの扱い

- モデル上の選択を正とし、古い描画結果から選択を復元しない。
- 座標が古い間も方向キー・数字の操作順を保持する。マウス位置の解決はその描画世代と対応させ、別の音符への誤入力を防ぐ。
- Workerの結果に文書ID・モデル世代・描画世代を付ける。古い結果は破棄し、新しい入力を上書きしない。
- 背景描画中に全画面を操作不能にしない。大きな構造変更だけは重複した構造変更を短時間抑制し、キャンセルと停止を受け付ける。
- 再描画後のスクロールは同じ譜面位置を基準に補正し、ユーザーの新しい移動を優先する。
- ベンドグラフや印刷プレビューなど、中間の表示要求は最新だけを処理する。実際の音符編集コマンドは省略しない。

### 取り消しと通知

取り消しでも保存時点の選択・必要な表示位置を一緒に扱う。ただし再生開始位置や譜面の先頭へ無条件に戻さない。途中計算の失敗を全曲再描画で隠す処理を減らす。

連続する同じお知らせはまとめる。通常の成功操作は必要以上に通知せず、失敗時は原因と直せる位置を示す。確認画面は、データが消える操作など実際に判断が必要な場面に限定する。

## 12. データと互換性

- 音符・奏法・コード・マーカーは既存の譜面モデルに保持する。
- 画面・印刷レイアウト等の譜面固有情報は、バージョン付きのTabStudioProject補足情報に保存する。
- カウントインの既定値、MIDIデバイス、パネル状態はアプリ設定へ保存する。
- 曲ごとの練習範囲・トレーナー設定は文書セッション情報に保持する。練習速度を操作するたびに楽譜のBPMや未保存状態を変えない。
- 設定・譜面・クリップボードのバージョンは分けて移行する。0.3.36のファイルと設定を読み込めることを必須にする。
- 他ソフトがTG本体を書き換えた場合は、現在と同じく古い補足情報を無条件に再適用しない。維持できなかった設定は読み込み情報で知らせる。
- 新しい奏法とレイアウトごとに、TG再読込・GP書き出し・他ソフト経由の互換性を試験する。独自設定が他ソフトでも完全再現されるとは保証しない。

## 13. 実装順序と完了条件

|---|---|---|

| B：編集基盤 | 編集コマンド、差分履歴、モデル参照、描画世代管理を追加。まず既存のフレット編集と奏法変更を移す | 現在の入力・範囲選択・再生位置・休符・保存の試験に合格 |
| C：1・2 | 共通の再生状態管理、カウントイン、スピードトレーナー | 停止・再開・拍子・ループ・テンポ変更・文書切替に合格 |
| D：3 | ベンドから順に奏法の詳細編集 | 表示・発音・範囲適用・取り消し・TG再読込の一致 |
| E：4・5 | 曲構成ナビゲーター、目的別・反復貼り付け | 構造変更への追随、通常貼り付けとの共存、大きな範囲でも入力応答を維持 |
| F：6 | 五線譜の直接入力、画面鍵盤、ドラムパッド、MIDIステップ入力 | 入力先の正確さ、和音・声部、切断時の後始末、実機入力を確認 |

## 14. 性能目標と検証方法

以下は未達成の設計目標。現在の性能として報告しない。

- 同じWindows実機で、168小節・2トラック・約4,000音の既存条件を比較基準にする。さらに多数トラック、高密度、連符・タイ・コード図のケースを追加する。
- 数字・カーソルの画面反応：通常は次の1〜2フレームを目標。
- 音符確定から方向キー移動：ウォーム状態で95%の操作が50ms以内を目標。平均だけでなく中央値・95パーセンタイル・最悪値を記録する。
- 通常の局所編集で50msを超えるメイン処理の連続占有を避ける。全曲の長さにほぼ比例する処理を入力経路から外す。
- 大きな貼り付けの受付表示：100ms以内を目標。完了時間は量と構造ごとに別途記録し、500msを超える場合は進行表示と取り消し可能な計算段階を用意する。
- 連続入力100操作で順序入れ替わり、欠落、別音符への適用がない。
- カウントと演奏の接続は音声ループバック等で測る。画面の時刻だけで合格判定しない。
- MIDI入力は実機の鍵盤で和音・素早い連打・デバイス切断を確認する。模擬イベントだけで動作確認済みとはしない。
- Macの入力・音声・PDF・ショートカットはMac実機で別途確認する。Windows上のパッケージ検証とは区別する。

### 重点回帰試験

範囲選択前の再生位置、青枠＋緑枠、Spaceのループ解除、Ctrl+Space、再生中のクリック移動、数字確定時だけの試聴、休符の選択で変形しないこと、右クリック選択、連続入力、取り消し・やり直し、文書切り替え、TG保存・再読込、既存設定の移行。

新機能は「表示できた」時点ではなく、保存・取り消し・キーボード操作・性能を含めて完了とする。長時間使った際のメモリ増加と履歴の保持量も測定する。

提案7のMusicXML、8の原曲音声同期、9の音声書き出し、および別提案の保存履歴機能は今回の実装対象に含めない。MIDIのリアルタイム録音、自動採譜、自由配置の出版用レイアウトエンジンも別案件とする。
