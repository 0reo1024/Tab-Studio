# 音声を再生（音声ファイル・YouTube）

プレーヤー → 「音声を再生（ファイル・YouTube）…」、またはミキサーの「音声」ストリップから開く。小さいウィンドウで、タイトル部分をドラッグすると動かせる（場所は次回も同じ）。

- **単体で再生（既定）**：▶／❚❚で再生・一時停止。波形をクリックするとその位置へ移動。速度は50〜150%（音声ファイルは音程を変えずに速度を変える）。譜面の再生とは関係なく鳴る。
- **曲と一緒に流す**：チェックを入れると譜面の再生に連動する（▶は譜面の再生ボタンと同じ）。「詳細設定」の「譜面の先頭」「テンポ補正」で位置を合わせる。波形のクリックは、その位置を譜面のカーソル位置に合わせる操作になる。
- 設定（ファイルの場所・連動するか・速度・位置・キー・音量）は譜面と一緒に保存される（`studiobacking`）。音声ファイル本体はコピーせず、元の場所を参照する。
- **C キー**でこの音声の再生／一時停止（設定 → ショートカットで変更できる）。Spaceはいつも譜面の再生／停止。ウィンドウを開いたままでも譜面の編集やショートカットは使える。
- ウィンドウを閉じても音声ファイルの再生は続く（ミキサーの「音声」ストリップで操作できる）。YouTubeは画面に表示している必要があるため、閉じると止まる。

## 音声ファイル（エンジンで再生）の仕組み

| 項目 | 仕組み |
|---|---|
| 対応形式 | MP3・AAC/M4A・FLAC・WAV・AIFF・Ogg Vorbis（symphonia。実ファイルで確認したのはMP3とWAV）。Opus/WebM/WMAは変換を案内する。30分まで。 |
| 読み込み | 開いたときに全体をデコードし、rubato（FFT方式）でデバイスのレートへ変換して、16bitステレオでメモリに置く（7分の曲で83 MB、デコード2.5秒＝174倍速）。ファイルにエンコーダー遅延の情報（MP3のLAMEヘッダー、M4AのiTunes情報）があれば、gaplessで除く。手元のMP3 2曲にはこの情報がなく、除く分はなかった（そのぶんは「譜面の先頭」で合わせる）。直近2ファイルはキャッシュするので、タブを切り替えても読み直さない。 |
| 単体再生 | エンジンの中に音声専用の再生位置を持ち、譜面の再生とは別に進む。最後まで行くと止まり、次の▶で頭から。 |
| 曲との同期（連動時） | ファイル位置 ＝ 先頭位置 ＋ 譜面の位置 × テンポ補正。プレーヤーがブロックの途中で起きる変化（カウントイン終了・ループの折り返し・曲の終わり）をフレーム単位で報告し、音声も同じフレームで切り替える。外部FXの遅延補償も同じだけ遅らせる。 |
| 練習速度・キー | 速度1.0・キー変更なしでは、メモリから直接読む（サンプル単位で正確、遅延なし）。それ以外はSignalsmith Stretchで、音程を変えずに速度を変える、またはテンポを変えずにキーを変える。プリロールと遅延の補正込みで、クリックの位置の誤差は0.5・0.75・1.25倍速で0.2 ms以下（テストで計測）。 |
| つなぎ目 | シーク・ループ・速度変更は5 msのクロスフェード、停止は5 msでフェードアウト。 |
| ミキサー | 譜面トラックのバス（1/√トラック数）の後、マスター音量・リミッターの前で混ぜる。ソロにすると譜面トラックは鳴らない（逆に譜面トラックをソロにすると音声は鳴らない）。 |
| 音量の自動調整 | ITU-R BS.1770の積分ラウドネスを測り、−16 LUFSにそろえる（市販音源は−5〜−9 LUFSが多く、そのままだとマスターのリミッターがかかり続ける）。オフにもできる。 |
| 位置合わせ | 「譜面の先頭」を秒で指定（±0.01／±0.1）。波形をクリックすると、その位置を譜面のカーソル位置に合わせる。録音のテンポが譜面と少し違うときは「テンポ補正」（80〜125%）。 |
| 編集との関係 | 音声の設定は音符の取り消し履歴に入らない（音符の編集を取り消しても先頭位置などは戻らない）。編集・取り消し・やり直しで音声が読み直されることはない。タブを切り替えると各譜面の音声に替わる（戻ったときはキャッシュから約0.07秒）。 |
| ファイルが見つからない | 保存時の場所になければ、譜面ファイルと同じフォルダーの同名ファイルを探す（フォルダーごと移動・コピーした場合）。それもなければ「ファイルを指定し直す…」を表示する。譜面はそのまま再生できる。 |

## YouTube（埋め込みプレーヤー）

YouTubeの規約に沿って、公式のIFrame Player APIで再生する。音声のダウンロードや抽出はしない。そのため次の制約がある。

- 音はエンジンを通らない：ミキサーのFX・ソロ・キー変更は使えない。音はWindowsの既定の出力から出る。ASIOで同じ機器を使っている場合は鳴らないことがある。
- 速度はYouTubeが用意する段階だけ（0.25〜2の0.25刻み）。中間の速度では一番近い段階で再生し、ずれたら合わせ直す。
- 単体では動画をそのまま再生する（速度はYouTubeの段階）。連動時は位置を見て補正する。ずれが150 msを超えたらシークし、シーク後のバッファリング分は着地位置から学習して先回りする。release版の実測ではずれは10〜139 ms（5回）。停止中は動画が勝手に再生されない（停止中の位置合わせは一時停止中の動画だけ。YouTubeは、読み込んだだけの動画にseekToすると再生を始めるため）。ループの折り返しなど0.5秒を超える飛びには、すぐ追従する。サンプル単位でそろえたい場合は音声ファイルを使う。
- 埋め込みが許可されていない動画（エラー101/150）は、理由を表示する。
- プレーヤーは規約に従って画面に表示する（356×200）。

## 検証

- `crates/tabstudio-audio`：`cargo test --lib`（72件）。音声関連は、オフセット位置のサンプル単位の読み出し、ファイル外の無音、練習速度でのクリック位置（0.2 ms以下）、5分間のドリフトなし、キー変更の周波数、フェード、WAVのデコード・リサンプル・ラウドネス、テンポ補正、エンジン経由のカウントイン開始フレーム、ループの折り返しフレーム、ソロ・ミュート、譜面の再読み込み後も音声が残ること、単体再生（再生・シーク・最後で停止・連動の切り替え）。
- `src-tauri`：`cargo test --lib`（リクエストの範囲チェック、移動したプロジェクトでのファイル探索）。
- `tests/backing.test.ts`：YouTubeのURL解析、速度の段階選択、追従ロジック、保存と読み込み。
- `scripts/tauri-backing-check.mjs`（release版、`TAURI_PROFILE=release node --import tsx scripts/tauri-backing-check.mjs [実際の.mp3]`）：読み込み、再生と停止、ミュート、ソロ、0.5倍速と−2半音（オーディオコールバックの過負荷0、最大1.1〜1.7 ms／10 ms）、波形クリックでの位置合わせ、保存して開き直す、ファイルが見つからない場合の再指定、実際のMP3（7分、−6.5 LUFS → −9.5 dB）、YouTubeの追従。
- `scripts/tauri-native-playback-check.mjs`：既存の再生・ループ・FX・NAMに影響がないこと。
- `cargo run --release --example backing_decode -- <file>`：デコード時間、ラウドネス、ブロックあたりの処理時間（0.5倍速で平均0.22 ms、最大0.94 ms／10.7 ms）。

## 未対応・今後

- 録音の頭より前（先頭位置がマイナスのとき、譜面の最初の部分）は無音。曲と連動しているときは、譜面が終わると音声も止まる。
- 自動の位置合わせ（発展）：音声からオンセット（スペクトルフラックス）とテンポを推定し、譜面のテンポマップから作った拍の列と相互相関を取れば、先頭位置とテンポ補正を自動で提案できる。途中でテンポが揺れる録音には、小節ごとの対応（ワーピング）が必要になる。
- signalsmith-stretchはビルド時にbindgenを使う。ASIOなしのビルドでもlibclang（LLVM）が必要。
